Multiscale Policy Optimization：把"按 token 记账"改成"按回合记账"

一句话：长程 Agent 是"一个回合做一件事、回合内逐 token 出动作"，而作者观察到 critic 的价值判断主要是在回合之间变化，不是一个 token 一个 token 地变。于是提出 MPO：用多尺度优势估计（MAE）+ 回合级重要性采样，把信用分配和策略更新对齐到"回合"这个尺度。为什么值得看：在搜索、工具调用、自动化任务上，4B 与 30B-A3B 两档模型都稳定超过强 RL 基线——它解决的是 Agent 训练里最实际的一个问题：一件做对的事，功劳该记在最后一步还是整个过程？这份答案是可复用的训练配方，不是又一个跑分。

1980 · 阿帕网第一次"全网瘫痪"：一个丢掉的比特，让互联网停了四小时

1980 年 10 月 27 日，阿帕网（ARPANET）爆发诞生以来最严重的故障，全网瘫痪约四小时——人类第一次有记录的大范围网络中断。起因低到不可思议：核心交换机 IMP 50 硬件异常，邻居 IMP 29 在持续丢比特位；而 IMP 不保存待重传的原始包，是把路由更新存在内存表里、重传时重新生成，校验和又只在较低频率上重算（为了省 CPU，当时的判断是"这种问题一年才一次"）。于是序号 44 的更新被重生成成了 40 和 8，而阿帕网用 6 位序列号 + 一条叫 LATER 的规则判新旧：44 比 40 新、40 比 8 新、8 又比 44 新——三个数字构成死结，全网无限循环广播，IMP 的 CPU 与缓冲被吃光，连维持线路的 HELLO 握手都排不上队。最讽刺的是修复方式：得给全网 IMP 打补丁让它忽略 IMP 50，而这些机器大多无人值守，只能通过网络本身去修网络——正常几分钟的广播，坏掉的网络里花了三四个小时。BBN 工程师 Eric Rosen 为此写下 RFC 789，修复分两层：改 LATER 的定义，以及让 IMP 具备资源保护与故障隔离（某进程占用异常时自动重置）。冷知识：中文互联网常把这天写成"阿帕网感染病毒而瘫痪"，但 RFC 789 通篇没用过 virus 一词，它写的是"一次离奇的硬件故障让某个高优先级进程失控，吞噬了其他进程所需的资源"。真正的"互联网第一病毒"要等到 1988 年 11 月的 Morris 蠕虫。
