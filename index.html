❓ 今日一问

都说"隔夜菜致癌"，那昨晚那盘青菜到底还能不能吃？

⚠️ 半真半假 · 说法夸大，但方向没错

"隔夜菜致癌"这句话被传了十几年，把最关键的剂量和储存温度两个词丢了。按公开检测数据：绿叶菜室温放 12 小时，亚硝酸盐明显上升、部分超过腌渍蔬菜 20mg/kg 的限量；放 24 小时部分能到 100mg/kg 以上；而4℃ 冷藏 24 小时，所有样品的亚硝酸盐都仍在安全值内。宁波市食品检验检测研究院对 30 道家常菜的实验结论一致：冷藏 24 小时基本不变，常温放置的绿叶菜才明显升高。

至于"致癌"：亚硝酸盐本身不致癌，需在胃里与蛋白质分解产物结合生成亚硝胺（2A 类"很可能致癌"），且要"长期、大量"两个前提。达到急性中毒剂量（0.3-0.5 克）要吃下约二十公斤隔夜菠菜——现实中吃不到。

真正该怕的不是亚硝酸盐
  • 细菌毒素才是不加热能去掉的：金黄色葡萄球菌肠毒素、蜡样芽孢杆菌呕吐毒素都耐热，反复加热也杀不掉，这才是上吐下泻进急诊的主因
  • 最危险的场景不是"隔夜"，是"放凉"：菜在桌上晾到彻底凉透才进冰箱，等于在 30-40℃ 的危险区间泡了七八个小时。世卫建议熟食常温存放不超过 2 小时（室温超 32℃ 时缩短到 1 小时）
这几样别留到第二天
  • 绿叶菜（菠菜、油麦菜、白菜、空心菜）：硝酸盐底子高，宁少炒一口
  • 凉拌菜（没经过高温杀菌）、海鲜水产（易产生耐热组胺）、溏心蛋（沙门氏菌）、常温久放的米饭
  • 可以留的：畜肉、全熟蛋、豆腐，以及冬瓜、南瓜、番茄、土豆这类瓜果根茎菜——密封冷藏、吃前彻底加热
🍽️ 餐桌怎么说：妈，隔夜菜不用整盘倒，关键看两点——趁热就密封进冰箱、别在桌上晾；绿叶菜和凉拌菜别留，肉和瓜类第二天热透了吃没事。真要扔，扔绿叶菜，别扔那碗红烧肉。

🧪 评测

kw-bench：用"真实调查型知识工作"考题，把前沿 Agent 框架拉下马

一句话：现有 Agent 基准大多是"给个简报，生成一份报告/表格"，再由评分表或另一个模型打分；kw-bench 换了个方向，专考知识工作里最贵的那部分——调查。题目取自真实项目，比如跨代 SAP 系统的五年增值税数据重建，用确定性方式评分（答案对错可验，不靠模型审美）。

发现：当实验室自家框架配上非自家模型时表现不佳，而 OpenCode、micro-cc 等独立框架反而能成功；Claude Opus 5.5 这类前沿模型几分钟就能完成弱配置做不到的任务。论文号 arXiv:2610.36405。

🔍 为什么值得看：它把"harness（框架）"当成一等公民来评测——同一模型换个壳，结果差出一大截。这对所有在选 Agent 工具的人都是提醒：你买的不是模型，是模型外面那圈循环、shell 和文件系统。
🔗 arXiv:2610.36405
💰 成本

AgentBaton：让强模型"干到一半"再交给便宜模型，API 成本降 65.9%

一句话：长程 Agent 任务里，能不能让贵模型和便宜模型在同一个任务内接力？论文系统比较了"交接方向"与"上下文传递"两个设计选择，结论很反直觉：

  • 便宜→贵 的交接通常不如全程用强模型，成本还没省下来
  • 贵→便宜 在合适的进度节点交接，能基本保持（甚至提升）准确率，同时大幅降本
  • 基于此做出轻量检测器 AgentBaton，从任务进度模式里学"什么时候该交班"。11 组模型对、两个基准上平均省 65.9% API 成本，准确率最高提升 8.8 个百分点
🔍 为什么值得看：这意味着"一次简单、时机正确的交接"就够了，不需要复杂的逐查询路由。对自建 Agent 的团队，这是最容易落地的一种省钱法——把开头交给强模型，收尾交给便宜模型。
🔗 arXiv:2610.35959
🧠 多智能体

DiscernMem：光"记住"不够，还要学会"什么时候别用这条经验"

一句话：多 Agent 团队会把经验存成"建议"复用，但存下来的经验可能本身有错，或被用在了不该用的场景——而"团队成功/失败"这个结果信号，无法区分"记忆需要修正"还是"记忆不该被调用"。DiscernMem 提出两个组件：

  • 缺陷感知记忆精炼：把"有这条记忆"和"没有这条记忆"的执行结果对比，诊断规则缺陷，并在当前与历史任务上测试修复，防止修一处坏一处
  • 边界学习元记忆：记录每条记忆的过往使用与效果，学习"该角色在什么上下文下该用、什么情况下该避开"

结果：在 Qwen3-4B 上，AutoGen / CAMEL / MacNet 三个系统平均分均为最高，比最强基线高 0.51-4.32 分；CAMEL 上的 PDDL 得分 37.71 vs 28.48。论文号 arXiv:2610.36652。

🔍 为什么值得看：这是"Agent 记忆"研究里少见的清醒视角：记忆系统的难点不是存，是删与不用。工程上对应一个很具体的建议——给每条经验记上"它上次生效的场景"，而不是只存内容。
🔗 arXiv:2610.36652
⏱️ 主动服务

ProactMem：主动型 Agent 的"记忆分层"，F1 提升 21.4%

一句话：主动型 Agent 要从持续观测和历史里预判"什么时候该出手"，但现有方法只用近期上下文或检索相关记忆，无法验证"某个规律是否还成立"。ProactMem 把历史组织成三层：近期事件、时间轨迹、行为规律——轨迹事实回查源事件，规律先用历史重放检验，再匹配当前条件。配套构建纵向基准 ProactiveStream。

🔍 为什么值得看：主动服务最容易翻车的地方是"用旧规律套新情况"。这篇的做法本质上是给 Agent 加了一道"这条经验还成立吗"的检查——对做提醒类、运维类产品的团队，是可直接借鉴的结构。

10月29日 · 互联网的生日
🌐 1969 · 第一条网络消息

1969 年 10 月 29 日 22:30，人类发出的第一条互联网消息只有两个字母："lo"

加州大学洛杉矶分校（UCLA）Boelter Hall 3420 室，学生程序员 Charley Kline 在教授 Leonard Kleinrock 指导下，试图登录 350 英里外斯坦福研究院（SRI）的机器。他敲下 "L"，SRI 那边电话确认收到；敲下 "O"，又确认；敲 "G" 时，系统崩溃了。

于是 ARPANET 上传出的第一个词是 "lo"——原本想打的是 "LOGIN"。约一小时后，连接才完整建立。

  • 四节点依次接入：UCLA（8 月 30 日首台 IMP 送达）、SRI（10 月 1 日）、UCSB（11 月 1 日）、犹他大学（12 月）
  • 链路只有 50 kbps，核心技术是分组交换与动态资源分配——这是它与电话网最根本的区别
  • 当时连"为什么要组网"都很模糊：早期几个月网络基本闲置，真正让大家用起来的是"和旧同事保持联系"这种社交需求
💡 为什么值得记住：第一个词是个"没打完的单词"，第一次连接还崩了一次。互联网的起点不是完美设计，是一次勉强成功的实验——56 年后的今天，它承载着几十亿人的日常。今天你发不出去的那条消息，比它当年完整得多。
