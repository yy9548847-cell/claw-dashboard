小鹏获批广州全域 L4 级 Robotaxi 示范运营，定名"小鹏悠游"

小鹏 Robotaxi 正式定名"小鹏悠游"，获准在广州全域开展 L4 级示范运营。同日，上海就《出租汽车条例（草案）》公开征求意见，提出依法有序推动自动驾驶技术在出租汽车行业的应用——一线城市开始给 Robotaxi "上户口"。

🛰️ 物理 AI

英伟达发布 Cosmos 3 开放世界基础模型：让机器人和自动驾驶"行动前先想"

NVIDIA 发布 Cosmos 3 物理 AI 开放世界基础模型：基于混合 Transformer 架构，首次把视觉推理、世界生成与动作预测整合进单一全模态模型，面向机器人与自动驾驶的"行动前思考"场景。同期开源的还有语音转录模型 Nemotron 3.5 Transcribe（40 种语言转写、31 种互译）及约 84.4 万小时语音数据集。

💡 解读：大模型分两条赛道：一条"会说"（聊天、写作），一条"会做"（物理世界操作）。Cosmos 3 押的是后者——机器人产业缺的从来不是胳膊腿，是"看懂房间然后想清楚怎么走"的脑子。

🔓 开源权重

Mistral 放出万亿参数模型 Mistral Large 4 权重：1T 总参、API 价格腰斩，但许可有"钩子"

法国 Mistral 开源 Mistral Large 4（内部代号 "Le Chonk"）模型权重：MoE 架构总参 1 万亿、每 token 激活约 520 亿、1M 上下文、支持文本与图像输入。正式版 API 价格从预览版 $1.36/$4.18 降到 $0.70/$2.10（每百万 token）。

  • 性能：Artificial Analysis 智能指数 26 分（同规模开放权重中位数 23），官方称编码智能体任务超过其他所有开源模型，token 消耗比竞品少 47%
  • 争议：许可条款要求任何把模型用于 Model-as-a-Service 的一方单独谈商业授权——HN 大量评论认为这只能叫"开放权重"而非开源
  • 定位：面向企业与政府"主权网络防御"，可自行下载部署
🔍 为什么值得看：这是"开源 vs 商用"路线的又一次正面交锋：权重给你，但商用要谈钱。对普通用户，免费能用；对企业，"能下载"和"能商用"之间隔着一份授权合同——下载前先读许可。

❓ 今日一问

一到换季就睡不好，是身体出毛病了吗？还是"秋燥"忍忍就过去？

⚠️ 半真半假 · 多数不是病，但"忍忍就过去"可能误事

换季睡不好，最常见的元凶其实是你没在意的温度。北京大学第六医院睡眠医学科主任医师孙洪强解释：入睡时身体需要把核心体温降下 0.5-1℃，靠手脚散热完成"热量转移"；换季时昼夜温差大，上床时凉得快、后半夜又冷得要产热保暖，交感神经一兴奋，睡眠就变浅、容易醒。再叠加光照变短打乱褪黑素节律、秋燥引起的鼻塞咽干，就有了"一换季就睡不好"的集体体验。

为什么
  • 体温调节压力变大：后半夜室温过低时，身体要耗能产热，人就睡不沉——盖被掀了盖、盖了掀，多半是这个原因
  • 光照变短：褪黑素分泌节律被打乱，晚上困得早、早晨醒得也早，这是节律波动，不等于失眠
  • 真正的预警线：每周约 3 次以上睡不着/早醒、持续 3 个月以上、已经影响白天状态——这时别硬扛，去睡眠门诊查原因
🍽️ 餐桌怎么说：妈，换季睡不好多半不是病，是屋里温度没调好——卧室别太热也别太冷，被子换厚点的、睡前少刷手机多见光；要是连着三个月每周都睡不好，那就别忍了，去医院看看睡眠科。

🧠 推理与偏见

《The Long Road to the Same Answer》：让推理模型"想得更久"，偏见并不会变少

研究者用 4 个模型家族、7 个模型、12,350 次 API 调用系统测试后发现：推理模型多花"思考 token"，认知偏见（锚定、框架效应等）的幅度并无显著下降。"慢思考能纠偏"这个心理学直觉，在当前推理模型上并不成立。

💡 为什么值得看：选型时的实用结论——别把"思考时长/推理档位"当质量保证。想减少模型偏见，靠的还是更好的提示设计与外部校验，而不是把推理预算拉满。
🔗 arXiv:2610.10049
✏️ 知识编辑

《EngramEdit》：事实知识可以"外挂"修改，不必重训模型

提出把事实知识从主干参数中剥离、单独编辑的机制：在 CounterFact / ZsRE 基准上编辑成功率近乎完美，多跳思维链下的准确率约为最强基线的 3 倍。

💡 为什么值得看：大模型改错知识一直很难——传统做法是重新微调。这篇指向"外置记忆"路线：频繁变动的知识（价格、规则、联系人）放外面改，模型本体保持稳定。对做知识库产品的团队，方向性很明确。
🔗 arXiv:2610.10533
🧰 Agent 技能库

《SkillForge》：Agent 的技能库要"优胜劣汰"，而不是只增不减

研究发现 Agent 技能库盲目扩张反而拖累表现：让技能"退休"（57.2% 被退休的技能此前处于稳定状态）并按需进化，整体成功率最高相对提升 7.8%。

💡 为什么值得看：和人类团队一样——技能多不等于强，关键在组合与新陈代谢。给自己搭 Agent 工作流的人，这条可以直接抄：定期清理没用过的技能，比持续堆新技能更有效。
🔗 arXiv:2610.09832
